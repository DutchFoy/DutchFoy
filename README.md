# Hey, I'm Dutch.

I'm making a career move into cybersecurity, focusing on Identity and Access Management (IAM) and identity governance.

My background is in hospitality operations and management, where I spent years working with people, processes, and the consequences when those processes break down. IAM interests me for some of the same reasons, with a new technical challenge: understanding who has access to what, why they need it, and whether that access is being managed properly.

I'm currently working through Microsoft security training and building hands-on labs with Microsoft Entra ID.

### What I'm working on

**[Microsoft Entra ID — Identity Lifecycle Lab](https://github.com/DutchFoy/entra-identity-lifecycle-lab)**

My first project follows a fictional hospitality company through employee onboarding, role changes, and offboarding.

I'm learning how to configure identities, manage access through groups, and verify that changes produce the intended results.

One question I'm particularly interested in: when a user's permissions are removed, how do we know their access is actually gone?

The lab is in progress, with configuration notes, testing, and evidence being added as I work through it.

### What I'm learning

- Microsoft Entra ID and Microsoft 365
- Identity lifecycle management
- Role-based access control and least privilege
- Authentication and access security
- Identity governance and access reviews

I like understanding why a process works before deciding whether it needs improving.

I'm new to the technical side of IAM, so there's plenty I don't know yet. I'd rather be clear about that, investigate properly, and build on what I can actually demonstrate.
